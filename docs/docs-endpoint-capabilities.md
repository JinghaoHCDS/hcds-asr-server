# `/docs` endpoint capability notes

This file is the source text for the FastAPI Swagger UI description served at
`GET /docs`. It describes only the capabilities implemented by the current
project code and validation records. Runtime model capability discovery still
comes from `GET /v1/models`; clients must not treat this page as a replacement
for model discovery.

## Agent quick start: official Skill

**Agents should read [the official LAN ASR Skill](/skill) first.**
`GET /skill` returns Markdown with capability selection, authentication,
ordinary transcription, real alignment, speaker segments, asynchronous jobs,
result retrieval, cancellation, recovery and quality limitations.
It is served from this release's `skills/lan-asr/SKILL.md`.

[Download the complete Skill and batch client](/skill/lan-asr.zip), or read
[the Python client source](/skill/asr_batch.py). The client uses Python 3.12+
and the standard library, takes a configurable server address, and preserves
local batch state. Downloading does not install or execute it.

Use `/skill` for the workflow, `/openapi.json` for exact API schemas, and
`/v1/models` for actual enabled models, backends and capabilities. All three
describe different parts of the same service; a documentation page does not
prove that a real model is ready.

## 2026-10-25 runtime and workbench

All inference paths (synchronous HTTP, asynchronous jobs, browser workbench,
edited-text alignment and model loading) share one bounded FIFO. Real model
invocations remain serial; a synchronous request cannot bypass the queue.
The registry also returns `engine_id`, `pipelines` and input specifications.

The `/v1/**` API keeps optional Bearer authentication and in-memory jobs.
`quality_profile=legacy` remains its default. Explicit Qwen
`quality_profile=quality_v1` requires a declared pipeline and enabled real
forced alignment; it does not turn a `/v1` job into a persistent workbench task.
`quality_v1` remains `validated=false` for long-recording accuracy.

The browser workbench at `/` and `/api/**` uses separate personal HttpOnly
sessions, owner isolation, SQLite tasks/checkpoints and seven-day retention
after terminal state. Default workbench upload size is 8 GiB; `/v1` remains
512 MiB. A Bearer token does not grant access to personal workbench tasks.
The OpenAPI paths below include the enabled workbench API too.

## MCP usage

This gateway can also be used as an MCP server through the client-side stdio MCP
bridge. The bridge reads an explicitly allowed local audio file and uploads it
to this same HTTP API; GPU inference still runs only inside WSL.

[Open the MCP setup tutorial](/docs/mcp)

The tutorial includes installation, MCP Host configuration, allowed-directory
security rules, all available tools, and MCP Inspector acceptance steps. MCP
does not add another LAN port and does not replace runtime capability discovery
through `GET /v1/models`.

## What `/docs` is

- `GET /docs` serves FastAPI's autogenerated Swagger UI.
- `GET /openapi.json` serves the OpenAPI document consumed by Swagger UI.
- `GET /redoc` serves FastAPI's autogenerated ReDoc page.
- `GET /docs/oauth2-redirect` is FastAPI's Swagger OAuth redirect helper.
- `GET /docs/mcp` returns the client-side stdio MCP setup tutorial as Markdown.
- `GET /skill` returns the official Agent Skill as Markdown; the complete
  installable folder is available at `GET /skill/lan-asr.zip`.
- `/docs` is documentation only. It does not load models, unload models,
  transcribe audio, expose GPU state, or prove that a backend has passed
  runtime validation.

## 2026-09-19 upgrade workflows

- `purpose=oral_analysis` requests real Qwen forced alignment and verbose
  evidence. Responses preserve the original-media timeline and expose actual
  char/word units, non-semantic reading groups, acoustic pause candidates and
  reproducible speaking-rate denominators. The server never invents fine
  timestamps by distributing sentence duration over characters.
- `purpose=podcast` selects the enabled MOSS diarization model and Anchor
  Replay without enabling unnecessary word alignment. Anonymous speaker IDs
  are scoped to one item, limited to four resolved identities, and uncertain
  segments remain `unresolved`/`mixed` instead of being guessed from content.
- Per-item `context` and `hotwords` are normalized, bounded and passed into the
  selected model prompt. The response reports `requested`, `applied`, `method`,
  truncation and ignore reasons; vocabulary is reference data, not a required
  output list or an instruction that can change service permissions.
- Long work uses asynchronous FIFO jobs. Poll with compact detail and fetch one
  full result after completion. The job store remains in-memory; submission
  idempotency prevents duplicate jobs during network retry but is not a
  persistent computation cache.
- The client-side `scripts/batch_transcribe.py` binds each media path directly to
  its metadata, rate-limits submissions, resumes local state and atomically
  writes `output/index.md`, `output/manifest.json`, and per-item
  `transcript.json`/`transcript.md`. This is a client workflow rather than a new
  multi-file HTTP endpoint.
- Current validation limits remain visible: Chinese short-form alignment and
  shorter Anchor Replay samples have real GPU evidence, while full 4–5 hour
  podcast speaker consistency still requires target-material acceptance. Read
  capability flags and quality warnings instead of assuming success from the
  selected purpose alone.

## Implemented HTTP API surface

The current FastAPI app registers these documentation and `/v1` endpoints.
Enabled workbench `/api/**` routes are also listed in `/openapi.json`:

| Method | Path | Implemented behavior |
| --- | --- | --- |
| `GET` | `/health` | Returns service status, version, host name, and best-effort local CUDA GPU visibility. |
| `GET` | `/skill` | Returns the official LAN ASR Agent Skill as Markdown. |
| `GET` | `/skill/lan-asr.zip` | Downloads the same Skill and its bundled Python batch client. |
| `GET` | `/skill/asr_batch.py` | Downloads the batch client as plain Python source. |
| `GET` | `/docs/mcp` | Returns the MCP installation, security, MCP Host configuration, tool, and acceptance tutorial. |
| `GET` | `/v1/models` | Lists declared models and their current runtime status and capabilities. By default this is the two Qwen3-ASR models; MOSS is listed only when explicitly enabled. |
| `GET` | `/v1/models/{model_id}/status` | Returns one model's lifecycle state, active request count, backend, token limit, timestamps, and VRAM field. |
| `POST` | `/v1/models/{model_id}/load` | Loads a declared model through the selected supported backend. |
| `DELETE` | `/v1/models/{model_id}` | Unloads one model immediately or schedules unload after active requests finish. |
| `DELETE` | `/v1/models` | Applies unload behavior to all declared models. |
| `POST` | `/v1/audio/transcriptions` | Accepts one uploaded audio file, validates requested capabilities, normalizes/splits audio, transcribes, merges results, and returns JSON, verbose JSON shape, plain text, or `202` queued job for audio over the sync threshold. |
| `POST` | `/v1/audio/transcription-jobs` | Creates an in-memory asynchronous transcription job in a single-worker FIFO queue. |
| `GET` | `/v1/jobs/{job_id}` | Returns queued/running/completed/failed/cancelled state. `detail=compact` is the default and omits transcript bodies; use `detail=full` once for the final result. |
| `DELETE` | `/v1/jobs/{job_id}` | Cancels queued jobs immediately or requests cancellation at the next running job phase/chunk boundary. |
| `POST` | `/v1/audio/alignments` | Exists only as a reserved endpoint and currently returns `422 capability_not_supported`. |

## Declared model capabilities

`GET /v1/models` declares these model IDs by default:

- `qwen3-asr-1.7b`
- `qwen3-asr-0.6b`

For both models, the base declared capability set is:

- `transcription: true`
- `backends: ["transformers"]`
- `streaming: false`
- `timestamps: []` and `forced_alignment: false` until the alignment gate is enabled
- `diarization: false`
- `segment_timestamps: false`
- language values as returned by `/v1/models`
- Chinese dialect values as returned by `/v1/models`
- `context_prompt: true`

After the real Qwen aligner smoke passes, setting
`ASR_ENABLE_QWEN_ALIGNMENT=1` changes the two Qwen declarations to
`timestamps: ["auto", "word", "char"]` and `forced_alignment: true`. The
transcription response then exposes the aligner's actual unit granularity,
source and status. CJK output is commonly character-granular; callers must use
the returned `granularity` rather than assuming every Chinese result is char
aligned.

The default model is controlled by `ASR_DEFAULT_MODEL` and defaults to
`qwen3-asr-1.7b`. MOSS cannot be selected as the default model in this
release.

When `ASR_ENABLE_MOSS=1` is set, `/v1/models` additionally declares:

- `moss-transcribe-diarize-0.9b`

Its first-release capability set is deliberately conservative:

- `transcription: true`
- `backends: ["transformers"]`
- `streaming: false`
- `timestamps: []`
- `forced_alignment: false`
- `diarization: true`
- `segment_timestamps: true`
- `execution_modes: ["native_long_form", "chunked"]`
- `auto_execution_mode: "native_long_form"`
- `max_new_tokens: 65536`
- `speaker_scopes: ["global", "chunk", "mixed"]`
- `validated_native_max_seconds: 1801.0`
- `automatic_fallback_chunk_seconds: 1800.0`
- `speaker_resolution_modes: ["off", "auto", "required"]`
- `speaker_resolution_method: "moss_anchor_replay"`
- `validated_anchor_replay_speakers: 4`
- language values: `auto` only. A 2026-07-10 adversarial WSL smoke showed
  `language=en` still returning Chinese for Chinese input, so `zh`/`en` are not
  declared until the model exposes a verified language-control mechanism.

For MOSS, `response_format=verbose_json` returns parsed
`segments[].start`, `segments[].end`, `segments[].speaker`, and
`segments[].text` when the model output is parseable. The `timestamps`
request parameter still does not support `word` or `char` timestamps, and MOSS
segment timestamps are not treated as forced alignment.
For `split_strategy=auto`, MOSS uses one native invocation through the validated
30-minute class window. Above 1801 seconds it explicitly falls back to chunks.
With `speaker_resolution=off`, labels remain chunk-local. With `auto` or
`required`, Anchor Replay carries speaker anchors across chunks and returns
anonymous task-local `speaker-NNNN` labels, with a maximum of four identities.
Uncertain or over-capacity segments remain unresolved and make the scope
`mixed`; they are never renamed and presented as verified global identities.
Anchor Replay limits each body chunk to 1200 seconds and uses an automatic
generation budget of at least 24000 unless the caller explicitly supplied a
value. Explicit `split_strategy=none` remains an advanced long-form challenge
and may return a controlled error on token, repetition or audible-speech
coverage checks.

## Transcription request behavior

Implemented form fields for `POST /v1/audio/transcriptions` and
`POST /v1/audio/transcription-jobs` are:

- `file`: required single audio upload.
- `model`: optional; defaults to the configured default model.
- `language`: defaults to `auto`.
- `response_format`: `json`, `text`, or `verbose_json`.
- `purpose`: `transcription` (default), `oral_analysis`, or `podcast`.
  `oral_analysis` selects verbose output plus real alignment; `podcast` selects
  diarization/Anchor Replay without unnecessary word alignment. Explicit form
  fields still override profile defaults.
- `timestamps`: `none`, `auto`, `word`, or `char`. Non-`none` values require a
  model currently declaring that capability; there is no silent downgrade.
- `backend`: accepts `auto`, `transformers`, or `vllm` syntactically, but only
  `auto` resolving to `transformers` and explicit `transformers` are supported
  by declared capabilities today.
- `quality_profile`: `legacy` (default) or `quality_v1`; the model's returned
  `pipelines` and capability checks determine which is supported. Quality_v1
  requires real forced alignment and remains a trial quality workflow.
- `quality_chunk_seconds`: optional quality_v1 candidate of 30, 60, 90, 120 or
  180 seconds, not an accuracy-validated optimal setting.
- `max_new_tokens`: optional and model-specific. Qwen defaults to `512` with a
  hard limit of `4096` in legacy; quality_v1 defaults to `4096`, respecting
  an explicit value. MOSS dynamically uses
  `max(2048, ceil(invocation_audio_seconds * 12))`, capped at `65536`.
- `context`: optional adapter prompt context, combined with hotwords and limited
  to `4000` characters.
- `hotwords`: optional JSON string array or comma-separated string, merged into
  adapter context.
- `pause_threshold_seconds`: alignment-gap candidate threshold, from 0.2 to
  10 seconds. A candidate is acoustic evidence, not a semantic pause label.
- `idempotency_key`: optional asynchronous submission key (maximum 200
  characters). Reuse with different audio or parameters returns
  `idempotency_conflict`.
- `split_strategy`: `auto`, `none`, `fixed`, `silero`, `energy`, or `vad`.
- `max_chunk_seconds`: optional per-request chunk upper bound.
- `overlap_seconds`: optional chunk overlap.
- `preserve_segments`: optional flag to return chunk-level details.
- `speaker_resolution`: `off` (default), `auto`, or `required`. MOSS only.
  `auto` returns a `diarization` summary and permits `mixed/partial`; `required`
  returns `422 speaker_resolution_incomplete` unless every valid segment is
  resolved. The method returns anonymous job-local `speaker-NNNN` identities,
  not enrolled names or biometric identity claims. A non-`off` mode requires
  `response_format=verbose_json`, because other formats do not expose segments.

Successful JSON responses include `execution`, `generation`, `context`, and
`timing`. `context` reports whether the prompt was requested and applied, the
method, and truncation/ignore information. Top-level `timestamps` are not created
by distributing sentence duration by character count; they come from the
declared aligner, and reading groups remain non-semantic. Clients should
consume `execution.mode`, `execution.speaker_scope`,
`execution.automatic_chunk_fallback`, `generation.generated_tokens`,
`generation.max_new_tokens`, and `generation.segment_coverage_ratio` instead of
inferring global speaker identity from the selected model ID.

Audio uploads are bounded by `ASR_MAX_UPLOAD_MB`, default `512`.
Each uploaded audio file is bounded to `21600` seconds, or 6 hours.
Synchronous requests over `600` seconds of detected audio duration are converted
to asynchronous jobs and return `202` with `status_url`.

## Async job behavior

The job manager is in-memory and process-local:

- Queueing shares the global FIFO with synchronous and workbench operations.
- Only one real model invocation runs at a time.
- `ASR_MAX_QUEUED_JOBS` defaults to `20`.
  The budget counts both active and waiting operations.
- Job result TTL defaults to `3600` seconds.
- A process restart loses in-memory jobs.
- `GET /v1/jobs/{job_id}` defaults to compact output. It does not repeat the
  accumulated transcript; `detail=full` returns the completed result.
- Reusing an asynchronous `idempotency_key` protects submit retries for the
  lifetime of the in-memory job. It is not a persistent computation cache.
- Progress reports real service phases and chunk completion counts; it does not
  invent token-level or frame-level Qwen progress inside a chunk.
- Uploaded job files and temporary work directories are cleaned after completed,
  failed, or cancelled jobs.

## Runtime modes

The service supports these adapter modes:

- `ASR_ADAPTER=mock` is the default local development mode and does not require
  CUDA, torch, Transformers, or a model cache.
- `ASR_ADAPTER=qwen` uses the lazy Qwen adapter and requires the WSL CUDA torch
  environment plus HF native Transformers dependencies to be installed and
  validated separately.
- `ASR_ADAPTER=registered` uses the internal engine registry; it does not
  automatically enable additional production models.

The real-GPU features are gated independently:

- `ASR_ENABLE_QWEN_ALIGNMENT=0` or unset keeps Qwen timestamp declarations
  disabled.
- `ASR_ENABLE_QWEN_ALIGNMENT=1` enables the lazy official Qwen forced aligner
  declarations after its real-GPU smoke has passed.

- `ASR_ENABLE_MOSS=0` or unset keeps MOSS out of `/v1/models`.
- `ASR_ENABLE_MOSS=1` adds `moss-transcribe-diarize-0.9b`.
- With `ASR_ADAPTER=mock`, all declared models use mock inference for local API
  tests.
- With `ASR_ADAPTER=qwen ASR_ENABLE_MOSS=1`, Qwen model IDs dispatch to the
  Qwen adapter and the MOSS model ID dispatches to the MOSS adapter.

The public model list is the same shape in both modes. Successful real Qwen
transcription requires the WSL GPU environment, not just the existence of
Swagger UI. Successful real MOSS transcription additionally requires the WSL
MOSS smoke test and dependency validation.

## Explicitly not implemented or not declared

These items must not be described as available capabilities:

- WebSocket streaming transcription. No
  `/v1/audio/transcriptions/stream` route is registered.
- vLLM as a declared first-release backend. The registry does not declare
  `vllm`; requests for it return
  `422 capability_not_supported`.
- SGLang Omni as a first-release serving path. It is not integrated into this
  gateway and must not be exposed on a LAN port by this service.
- A standalone alignment API. `/v1/audio/alignments` remains reserved and
  returns `422 capability_not_supported`; verified alignment is requested on
  the transcription routes.
- Guaranteed cross-chunk speaker attribution. Anchor Replay can resolve up to
  four task-local speakers, but uncertain segments remain `unresolved` and the
  response explicitly reports `mixed` rather than guessing from content.
- Multiple-file transcription in one request. The implemented routes accept a
  single `file` upload.
- Redis, Celery, distributed workers, parallel model inference, public tunnel
  exposure, or MiMo-V2.5-ASR. SQLite and the browser workbench are implemented;
  `/v1` jobs retain their separate in-memory semantics.

## Adversarial review checklist

Use this checklist when changing `/docs`, `/openapi.json`, or this file:

- If an option appears in a Pydantic/FastAPI schema only because the parser
  accepts its string value, verify whether runtime capability validation also
  permits it.
- If a capability is not returned by `GET /v1/models`, do not document it as
  supported.
- If a future branch exists in adapter code but the registry does not declare
  it, document it as unavailable.
- If a feature requires WSL CUDA validation, distinguish code support from
  environment readiness.
- Keep port references limited to the service API port `18080`; do not add
  historical test ports or expose worker ports.

## Optional API authentication

When `ASR_API_TOKEN` is configured, every `/v1/**` request requires an
`Authorization: Bearer <token>` header. Missing or invalid credentials return
`401 unauthorized` in the standard error envelope before the upload is read.
Health and documentation remain public. Use Swagger Authorize to authenticate.
The deployed systemd unit reads the optional project `.env`; a plain Python
process and the MCP bridge do not load it automatically.
