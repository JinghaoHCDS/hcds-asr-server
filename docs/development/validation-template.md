# 验收记录模板

每份公开记录只保存经批准的脱敏摘要。原始录音、正文、账号、机器路径、凭据、数据库和完整失败日志不写入 Git；需要原始证据时先确认私有位置及保留范围。历史已公开不自动等于继续公开授权。

## 版本与环境

- 验收日期、平台／发行版、Python／uv／Node／FFmpeg 版本：
- 源码 commit、是否有未提交修改及对应文件摘要：
- 产品包 SHA-256、manifest／前端构建身份、锁文件身份：
- 配置：只列非敏感且影响复现的参数，地址／目录使用逻辑标识：
- GPU、torch、CUDA、capability（仅实际 GPU 验收填写）：
- 样本逻辑 ID、SHA-256、来源／许可范围、时长和音频规格：
- 开发集或独立验收集、参考文本的获准私有证据编号：

不能用 commit 单独替代未提交源码或前端覆盖身份；无法还原时明确写出缺口。

## 质量与性能解释

- CER／WER、术语、漏词、幻觉、重复、字幕偏移的方法及分母：
- 样本规模、语言／声学条件、参考来源、开发／验收分离：
- 冷／热加载、总耗时、推理耗时、GPU／RSS／磁盘峰值：
- MOSS global／chunk／mixed、partial／unresolved 与尾部覆盖：
- 内容完整性缺口、未分类声音、人工回听结论或未核实状态：
- 对照版本、相同输入／参数、轮数和测量扰动：

合成循环只证明相应资源边界；对齐成功不证明文字正确；短样本、CPU／mock、窄屏模拟不替代真实长音频、GPU 或手机实机。没有实际运行的行标“未执行”，不得留成含糊“通过”。

## 证据与结论

- 公开证据：脱敏指标／摘要位置、校验摘要：
- 私有证据：仅批准的逻辑编号，不写私人路径／原文：
- 本次执行的是方案审查、隔离演练还是生产实际操作：
- 失败、阻断与未验收项：
- 后续工作及具体关闭条件：
- 回滚结果或仍未实际执行：

正文完成后检查相对链接、图片和公开 diff（含删除行）；确认没有重新引入敏感证据或把历史授权写成下一次授权。新证据另建绑定版本记录，保留既有失败与限制。
