# 转录恢复与单机服务健壮性设计

本文保留已实现恢复机制的理由与不变量，替代 2026-10-26 专项派发计划。当前行为以[工作台契约](../reference/product-workbench.md#转录恢复与服务就绪)和[平台运行契约](../reference/asr-platform-runtime.md)为准；实际证据见[专项验收](../validation/2026-10-26-transcription-resilience.md)。工程功能已实现不等于质量专项关闭，未完成门槛见 [roadmap](roadmap.md)。

## 保住进度并如实报告缺口

schema 5 从 schema 4 事务迁移，保留全部 MP3、成功块、检查点、版本和保留期，不执行旧清库工具。基础 `quality_v1.4` 指纹与恢复 `recovery_v1.0` 分离，旧成功块摘要校验后只读复用；失败原始调用须有持久错误和原时间窗口来源，不能凭临时文件猜测。

原始块恢复耗尽后继续后续原始块，子段失败也不提前放弃其他子段。稀疏成功区间可恢复，但不能把局部成功拼接成完整稿。缺口任务保持 `failed/quality_incomplete`，部分 TXT 明示不完整和区间，JSON 保留 gaps／completeness；没有完整真实时间信息时不导出字幕。

ASR 原稿在对齐前落盘；对齐失败只恢复对齐，不重识别。attempt／generation 与版本 fence 防止取消、删除、编辑和新尝试后的晚到提交；文件与数据库提交须经 owner／版本核对，清理失败不能发布已释放资源的假终态。

## 有界恢复与声音证据

语言恢复需要最近已确认非空块的一致语言和时长证据；auto 空稿不是任意猜语言的依据。每原始块最多三个恢复动作，正常合并复核同账本；实际重复音频总预算不超过首次输入 30%，先持久预扣再调用。普通重试和重启不重新赠送预算。

二分／四分按真实窗口独立评估，不丢弃其他子段；候选仍经过截断、重复、真实对齐及有声遗漏检查。声音检测没有阴性证据，不等于已证明有人声或漏词。音乐、音效、呼吸和检测不可用保持未分类／具体原因，界面称“待回听确认”，不把整块当已证明遗漏台词。

## 故障恢复、就绪与排空

基础设施恢复每操作最多一次、任务累计三次，持久退避释放调度槽位，到期按新提交进入 FIFO。连续 fatal worker 错误触发冷却，真实推理成功才清零；无法确认旧 worker 退出时全局隔离 GPU，禁止并存第二个 worker。质量空稿不触发基础设施熔断。

分阶段 deadline 默认继承旧 inference 上限，观测超时只记事件；收紧必须基于目标机器实测。独立 watchdog 观察事件循环失联，不用 GPU 利用率或界面百分比中断长调用。

`/health` 表示存活，`/readyz` 表示推理准入。维护、熔断和排空仍允许已有文字、回听、导出、登录与取消；管理员 drain 在安全边界保存进度。发布与回滚见[升级指南](../guides/upgrading.md)，不复用历史发布授权。

## 验证边界

确定性回归覆盖恢复预算、稀疏进度、fence、重复故障、取消删除和清理；真实 CUDA 回收、模型质量、磁盘资源、八小时持续运行分别验收。故障注入只用隔离数据和自有任务，不对用户活跃任务直接 kill。保留有效失败记录，不用总体平均值掩盖新增整段遗漏或幻觉。
