# 工作台音频与容量设计

本文保留 2026-10-26 MP3 改造的长期设计理由，替代已完成实施清单。当前 schema 6 行为以[工作台契约](../reference/product-workbench.md)及[运行契约](../reference/asr-platform-runtime.md)为准；[当时验收](../validation/2026-10-26-workbench-audio.md)记录实测范围，未证明六小时质量或完整听感通过。

## 持久 MP3 与操作 PCM

持久资产采用 192 kbps CBR MP3，界面称“高质量回听 · MP3 192 kbps”，不称无损、不承诺恢复低质源细节。44.1／48 kHz 源保持，其余转 48 kHz，单／双声道保持，多声道固定混为双声道；记录首条音轨的实际索引。

MP3 需要完整解码、有效帧与规格检查后才能复用，扩展名或平均码率不足。MP3 和所需视频均原子提交并持久化 ready 元数据后才删除唯一上传源；失败保留源文件。首次转录、重试和编辑对齐使用同一 MP3，按需生成受控 PCM，避免跨操作长期保存大型 WAV。

操作内转录、复核及初始对齐共享同一 PCM 资产；owner 等消费者退出、删除 PCM／分片并结算 lease 后发布终态。编辑对齐完整解码后按整数采样取窗口，避免 MP3 随机截取的帧边界偏移。重试不重复编码 MP3。

检查点绑定 MP3 摘要、解码规范、PCM 摘要和模型／流程／请求／词库身份。跨操作不使用临时路径或 inode；不一致明确拒绝，用户可显式从头重试。

## 互斥容量账本

`saved_bytes`、`text_bytes`、`temporary_bytes` 与未兑现 `reserved_bytes` 分开，前三项构成 used，加预留构成 allocated。准入同时检查个人／全局 allocated 和物理磁盘承诺，落盘后的预留不能再计一次。source、MP3 与 PCM 同时存活的峰值按实际字节计；删除失败不提前释放账目。

日常查询读账本，启动及低频维护核对文件。Range 回听／回看只提供归属校验后的 ready MP3／MP4，使用私有缓存；删除等待活跃消费者退出，晚到结果不得复活任务。

## 历史 schema <4→4 边界

当时从旧持久 WAV 切到标准 MP3，未实现旧任务／WAV／检查点迁移；非空旧库通过 `schema_reset_required` 拒绝启动，离线重置保留账户与公共词库。该次发布的数据删除及临时备份处理属于历史决定，**不是未来重置授权**。

当前 schema 4/5→6 保留全部任务与文件，禁止套用旧清库步骤。升级／备份／匹配回滚以[升级指南](../guides/upgrading.md)为准。既有源样本和原始验收材料的公开范围仍待确认，不因本地文档整理而改变。

## 视频资产补充

schema 6 保留标准 MP3 作为唯一识别音频，新增独立 H.264/AAC 视频回看。视频封装使用 delay_moov 保留音画首帧偏移，随后在已预留完整副本的空间内 faststart 重封装。不能将音画两条流分别归零；持久化视频到音频的时间映射。视频失败保留源供重试，MP3 无需重做。完整参数及状态以[工作台契约](../reference/product-workbench.md)为准。


视频与音频并行时，两者共享 source，但持有各自预留与临时文件集合。`video_reserved_bytes` 是任务总预留中的视频剩余承诺，不再额外加入 allocated；音频结束时不扫描或删除视频临时文件。实际写入与预留兑现以同一 owner 更新，避免另一个操作观察到尚未批量入账的文件后重复计费。低频容量修复跳过任一 owner 仍活跃的任务。

长视频的 GPU 路径边编码边完整解码输出，重封装再核对包摘要，避免串行重复解码造成等待。音轨固定两秒封装分片，整段连续 AAC 编码；视频切片的时间关系由真实信号标记检查。默认 15 帧适用于面试回看，30 帧仍可配置但增加工作量，不能把 GPU 编码加速等同于全流程耗时保证。
